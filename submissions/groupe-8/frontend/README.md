# EnedisPO — frontend

A decision-support screen for dispatching Enedis field teams during a storm. The engine recommends, and the crisis manager accepts or overrides.
React + TypeScript + Vite, MapLibre GL with deck.gl layers, OpenFreeMap "liberty" street basemap (OpenStreetMap, no API key).
Hackathon mock-up: it uses the Enedis colours but not the Enedis logo or wordmark.

## Running it

Requires Node ≥ 20.

```bash
npm install
npm run dev        # http://localhost:5173
```

`npm run dev` regenerates the mock scenario first if the CSVs in `data/` have changed (`npm run generate` forces it).
For the demo: open in Chrome in full screen (F11) at 1920×1080. The layout also works down to about 1366 px wide.
The basemap (`https://tiles.openfreemap.org/styles/liberty`, fallback: CARTO Voyager `https://basemaps.cartocdn.com/gl/voyager-gl-style/style.json`, set in `src/components/map/territory.ts`) and the relief (AWS Terrain Tiles) need an internet connection. The departments, communes, labels, incidents and teams are local, so without a connection the territory still displays on a plain background.

Stress test: open `http://localhost:5173/?equipes=50` to keep half the teams of each site (any percentage works). With half the teams, the 90 % restoration estimate goes above 48 h and the FIRE flag appears.

To check how the 90 % cell displays, `?r90=30`, `?r90=45`, `?r90=54` or `?r90=null` forces the estimate in the mock (on target, close to the limit, over 48 h, no estimate).

Keyboard: `Space` play/pause, `←` `→` step by 30 min, `↑` `↓` move through the recommendations, `Entrée` accept the one in focus, `C` open "Changer d'équipe" (then `↑` `↓`, `Entrée`, `Échap`), `Échap` close the copilot. Playback speeds: ×1 = 1 min of crisis per second, up to ×120 = 2 h per second.

## Where the data comes from: the swap point

Everything goes through **`src/data/source.ts`** (`CrisisSource` interface). Nothing else in the UI knows where the data comes from.

| `VITE_DATA_SOURCE` | Implementation | |
|---|---|---|
| `mock` (default) | `src/data/mock/mockSource.ts` | Loads `public/mock/crise_027/scenario.json` and runs the naive engine `src/data/mock/engine.ts` in the browser. Decisions trigger a re-simulation. |
| `api` (default page: **live**) | `src/data/live/liveSource.ts` | The crisis in real time: polls `/live/state` every second, the clock is the backend's (= now). Alerts and team reports come from the separate field simulator (`python -m simulator`, repo root). |
| `api` + `?mode=replay` | `src/data/api/apiSource.ts` | « Revoir une crise passée »: the FastAPI service at `VITE_API_URL` (default `http://localhost:8000`) replays a past crisis (`?crise=CRISE_051`) in accelerated time. |

The right panel has four tabs: **Plan** (the proposal to validate), **Équipes** (every team by status with its shift
end / return time and group, plus the roster explained: 12 h on / 12 h off, groups A/B/C on a 48 h band), **Copilote**
and **Journal**. In live mode there is no playback and no reset: the field decides what happens next.

To plug in the real engine:

```bash
VITE_DATA_SOURCE=api VITE_API_URL=http://localhost:8000 npm run dev
```

then adjust the routes in `apiSource.ts` if they differ from the proposed ones:

```
GET    /crises/{id}/meta                 -> CrisisMeta
GET    /crises/{id}/timelines            -> { ours: Snapshot[], reference: Snapshot[] }
POST   /crises/{id}/decisions            body: DecisionInput & { kind: "accepted" | "overridden" } -> timelines
DELETE /crises/{id}/decisions            -> timelines (resets the decisions)
GET    /crises/{id}/what-if?team_share=  -> { score, baseline }   (optional, used by the copilot)
```

The types are in `src/data/contract.ts`. Fields added to the original contract are marked `ADDED`.
`fixtures/crise_027/snapshots_*.json` are full examples of what the engine should return (generated by the mock).

## Mock scenario

`scripts/generate-mock.ts` (`CRISIS=CRISE_027` by default):

- joins `coupures_v2_100_crises.csv` to `poste_v2.csv` and drops incidents whose substation is unknown (none in CRISE_027; the 5 orphan incidents belong to CRISE_003/024/041/051/075);
- creates one team per `nb_equipes` unit at each site (63 teams, named `Muret-3` and so on);
- staggers schedules: about 1 team in 5 starts off duty, the others have 3–12 h left in their shift.

Mock engine rules (deliberately simple; real optimisation is out of scope):

- 30-min steps; travel time = straight-line distance × 1.3 at 55 km/h, plus 15 min of preparation;
- a 12 h shift, then 11 h of rest at the site; no assignment if travel + repair exceeds the remaining shift;
- **reference**: first reported incident first, nearest feasible team;
- **copilot (mock)**: greedy on clients (×2 if sensitive) per hour of travel + repair, nearest team;
- the cost of an alternative (`deltaScore`) is a first-order estimate: clients × extra travel time. It ignores knock-on effects on the other assignments;
- a recommendation that is not touched is executed at the step time, so playback continues on its own.

```

  data/contract.ts        engine ↔ UI types
  data/source.ts          swap point (mock | api)
  data/mock/              mock engine + mock source
  data/api/               FastAPI client, replay of a past crisis (+ shared helpers: roads, learning loop)
  data/live/              live source: real time, polling /live/state
  state/store.ts          global state (zustand): clock, view, decisions, toasts
  state/clock.ts          playback loop + keyboard shortcuts
  components/             TopBar (mode switch), MapView (deck.gl + SVG lines), RecPanel/RecCard/OverridePanel, TeamsPanel,
                          Copilot, Timeline, ComparisonChart
  copilot/                explanations and stubbed answers
  styles/tokens.css       ALL the colours and fonts (sampled from the Enedis website)
  components/map/         basemap setup (French labels, relief, department highlight) and site label placement
scripts/
  generate-mock.ts        CSV → scenario.json + fixtures
  copy-maplibre-worker.mjs  serves the MapLibre worker untouched (Vite dev breaks it otherwise)
  build-geo.mjs           france-geojson → public/geo/territory.json
```

## Map and visual identity

- **Geography**: `public/geo/territory.json` is generated by `scripts/build-geo.mjs` from the [france-geojson](https://github.com/gregoiredavid/france-geojson) dataset (Licence Ouverte / Etalab). It contains the full-resolution boundaries of departments 09, 31 and 32, their outline split into outer and shared borders (shared ones are drawn thinner), and the communes for the optional "Saturation par commune" layer. The output is committed. To regenerate it, download `departements/<code>-<name>/departement-<code>-<name>.geojson` (saved as `d09/d31/d32.geojson`) and the matching commune files (saved as `c09/c31/c32.geojson`) into one folder, then run `node scripts/build-geo.mjs <folder>`.
- **Basemap and highlight**: a full street map you can pan and zoom anywhere (minimum zoom: all of France), with French labels and a km scale bar. The three departments get an 8 % blue fill under the roads, and a blue outline with a white casing above the roads but below the place names. Their name labels hide at street zoom. "Recentrer" returns to the three departments; "Haute-Garonne" fits department 31. Below zoom 7, site labels are hidden and markers shrink. Incidents, teams, sites and routes always draw above the basemap.
- **Sites**: a square holding the number of available teams; the name shows on hover and, from zoom 10, as a label.
- **Map labels** are placed by `src/components/map/labels.ts`. They never overlap each other, the basemap's city and town names, the legend or the buttons; when the full label doesn't fit they fall back to "4 dispo". Town, road and river names come from the basemap.
- **Sites vs teams**: the 18 sites are fixed blue squares labelled with their number of available teams. Teams that are idle at their site are counted in that label and not drawn. Teams on the move are blue diamonds.
- **90 % estimate** (`kpis.restore90Hours`, top-right cell): hours since the start of the crisis until 90 % of the customers cut so far are restored, following the current plan. The mock takes the restoration times from its own simulation, so in the mock every incident is always scheduled. The real engine returns `null` when its plan does not reach 90 %. Above 48 h the cell turns red and shows the FIRE flag; the state only changes when the value crosses 48 h.
- **Crisis timeline** (bottom band, `CrisisTimeline.tsx`): customers cut over time, solid in the past and light/dashed for the plan's projection, new incidents, teams working or resting, and the milestones (peak, 50 % and 90 % restored, 48 h target, end of crisis) written on the axis, plus a one-line summary. The reference strategy is not shown there; it stays in the data layer.
- **Layout and type**: one 62 / 38 grid shared by the header, the map and recommendations, and the bottom band. Outfit (tabular figures) is for figures and main titles; Public Sans for everything else. Five type sizes (`--fs-1`…`--fs-5`) and one spacing scale (`--s-1`…`--s-6`) in `tokens.css`. Screenshots before/after the design pass: `docs/screenshots/`.
- **Colours**: everything comes from `src/styles/tokens.css`. Contrast-adjusted variants are used for text (`--green-text`, `--waiting-text`, `--blue-muted`). 
- **Dev visual checks**: `npm run dev` exposes `POST /__shot` (saves under `.shots/`, or `SHOT_DIR`), and `window.__page('name')` (from `src/dev/capture.ts`) saves a full 1920×1080 capture of the page, map included. Neither is part of the build.
